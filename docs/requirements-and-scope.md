# 需求范围与验收映射

依据原题《AI 驱动的股票市场大势研判》锁定 24 小时 MVP。入口保持为市场总览、证据地图、状态切换、证据溯源和 AI 继续研究；本次仅修正真实数据、AI、合规和证据门槛，不扩展产品功能。

## 必须交付映射

| 原题要求 | 当前实现 | 验收边界 |
| --- | --- | --- |
| 市场状态框架 | 五个核心维度规则引擎；输出状态、置信度、主要矛盾和切换条件；至少 3 个有效核心维度且市场宽度有效才形成整体判断 | 缺证据时 Hard Gate 直接拒绝方向性判断 |
| 真实市场证据 | 扶摇指数快照/日线、全市场分页快照、涨停/跌停池 | 结构、宽度、风格和情绪可评分；缺页、低覆盖、过期或冲突不补造 |
| 流动性 | 扶摇提供当日全市场成交额；可选 iFinD 提供历史日频基准 | 同口径最近 20 个有效交易日均值和收盘后扶摇快照均有效时评分；缺失/过期/冲突时不评分 |
| 估值与事件 | 估值维度保留；可选 iFinD `search_news` 提供事件 evidence | 估值 unavailable；事件无有效 iFinD 结果时 unavailable，成功时可追溯但不参与状态评分 |
| 事实、归纳、不确定区分 | 服务端工具事实、规则结论与数据不足分层显示 | 证据可查看原字段、来源、时点和计算口径 |
| 基于问题制定研究计划 | 真实 LLM 先生成受限 Research Plan，服务端校验字段 allowlist | 计划后复用最近 3 分钟的校验快照（过期时才取数）；显式行情刷新强制更新；禁答请求在计划及数据调用前拦截 |
| AI 解释 | 第二阶段 LLM 只解释结构化 evidence，并须引用有效 evidence ID | 数字事实由服务端计算/渲染；模型异常时不使用模板冒充回答 |
| 金融合规 | 输入端意图拦截与输出端二次合规检查 | 覆盖买卖、荐股、仓位、加减仓、目标价、止损、确定性涨跌、收益承诺 |
| 异常处理 | Key 缺失、接口失败、分页不完整、缺字段、冲突和过期均显式处理 | 扶摇模式绝不静默回退演示数据；Hard Gate 有自动化测试 |
| Web 与文档 | 既有首页、API、证据结构；README、AI 使用记录和测试说明同步更新 | 32 项自动化测试通过；Sites 生产发布另行记录线上复测结果 |

## 当前代码数据范围

- 已接入：扶摇。市场快照与指数历史在本次实时只读联调成功。
- 扶摇提供行情结构、市场宽度、风格轮动和情绪核心证据；不受 iFinD 可用性影响。
- iFinD 是可选补充：`get_security_indicators` 提供全 A 历史成交额以补齐流动性 20 日基准，`search_news` 提供事件 evidence。发生源间冲突时保留两源事实并暂停流动性评分。
- 估值仍 unavailable；iFinD 未配置、失败或返回空时，事件 unavailable，流动性不评分；不以 demo 值填充。
- 本轮代码和本地测试未部署到私有 Site；生产运行时 secret 和线上 iFinD 行为需要后续发布前确认。

## MVP 保留与暂缓

保留现有 UI、Evidence 结构、状态解释、证据抽屉、指数对比、切换条件和追问能力。个股推荐、目标价、涨跌预测、收益承诺、仓位建议、交易/回测、持仓画像、登录、实时推送和新页面不在范围内。
