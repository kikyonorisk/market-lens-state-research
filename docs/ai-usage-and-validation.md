# AI 使用与验证记录

## AI 参与环节

- OpenAI Codex 协助实现扶摇数据适配、市场状态规则、AI Research 两阶段调用、程序级合规检查、自动化测试和本文档。
- 应用内使用配置的 OpenAI-compatible LLM（当前 DeepSeek endpoint/model）。第一阶段解析用户问题并生成 JSON Research Plan；程序随后调用市场数据工具；第二阶段只接收研究计划和结构化 evidence，按 evidence ID 生成解释与不确定性。
- 市场指标、维度分数、Market State、置信度、主要矛盾、切换条件和引用事实均由服务端数据/规则代码计算或渲染。LLM 不调用金融数据工具，不计算或补写金融事实；模型生成的数字陈述会被二次校验。

## 程序级安全边界

- 买卖、个股推荐、仓位、加减仓、目标价、止损、确定性涨跌和收益承诺等问题在 Research Plan、市场刷新和数据工具调用之前拦截。
- 模型输出经过第二次合规校验；规则按上下文识别具体荐股/交易动作、仓位安排、目标/止损位、方向预测和收益承诺，不因“上涨家数”“市场涨跌幅”“止损字段缺失”等孤立词语误杀普通研究。命中的越界文本或未核验数值陈述会被丢弃，不会以模板答案伪装成真实模型回答。
- 核心证据少于 3 个有效维度，或市场宽度分数/上涨占比缺失时，服务端 hard gate 在解释模型调用之前阻止整体方向性回答，并清空主要矛盾与切换条件。
- 模型未配置、上游失败或响应格式无效时明确报告不可用；不静默切换到规则模板。
- Research 默认复用与首页共享的最近 3 分钟通过校验的聚合快照；底层指数快照、全市场分页/涨跌停池、历史日线分别按 2、4、45 分钟 TTL 缓存。用户刷新会重新检查数据，但不会绕过仍有效的资源缓存，避免重复抓取重接口。
- 每个扶摇 HTTP 请求独立创建 AbortController，指数/全市场/历史/涨跌停接口分别设置 18/25/30/25 秒 timeout，网络或超时最多重试一次；全市场分页并发限制为 3，所有扶摇请求总并发限制为 4。单路失败不会取消其他请求。
- 请求失败后仅在资源 freshness threshold（指数 15 分钟、全市场/涨跌停 20 分钟、历史日线 3 小时）内回退最近有效快照；页面显示“部分数据”“最近有效快照”和原始来源时点。超过 threshold 不继续使用旧数据、不显示 LIVE；现有 Hard Gate 规则保持不变。

## 人工复核与已知限制

- 真实数据凭证由 Site 运行时以 secret 保存；本文件不记录密钥、原始认证头或可识别凭证的日志。
- iFinD 的历史本地适配探索包含 `get_security_indicators` 与 `search_news`，代码和自动化测试保留。因线上 MCP 稳定性未达到生产要求，本次 MVP 生产默认关闭 iFinD（必须显式 `IFIND_ENABLED=true` 才调用），不依赖其凭证、网络或可用性；事件不会进入当前生产 Research evidence。未来 opt-in 启用时仍受数据许可约束，未确认全文许可前不得展示或发送新闻正文。
- 阈值是透明规则，不代表历史回测验证过的预测模型。市场研究结果不构成投资建议；尚未完成正式历史回测或人工投研校准。
