新增/更新的关键覆盖：

| 范围 | 验收内容 |
| --- | --- |
| 状态与 Hard Gate | 可用核心维度少于 3 个（包括遗留旧分数）时不生成方向状态、主要矛盾或切换条件；市场宽度分数或上涨占比缺失时同样拒绝整体判断 |
| 扶摇真实数据映射 | 指数快照、历史日线、风格相对收益、全市场分页宽度/成交额、涨跌停池映射到 evidence；分页缺失、总数不一致或覆盖不足时不拼接、不补造 |

| 分层缓存与降级 | 首页/Research 共用 3 分钟聚合缓存；指数快照 2 分钟、全市场分页/涨跌停池 4 分钟、历史日线 45 分钟；同资源并发请求合并；有效期内失败可用 LKG 并显示真实时点，超过 freshness 时限不可评分且 Hard Gate 生效 |

| 合法主题回归 | 8 类市场状态、宽度、风格、行业、流动性、情绪、事件与历史比较问题均完成 Plan → evidence → LLM 解释 → 有效 citation，自动化 fixture 8/8 |
| 违规输出回归 | 8 类荐股、买卖动作、仓位安排、目标价、止损、方向预测和收益承诺的模型输出全部被二次检查拦截，自动化 fixture 8/8 |
| 新闻展示许可保护 | iFinD 事件 evidence/API/Research 只保留标题、日期、来源、链接；即使 MCP 返回正文，适配器也不把正文传给页面或 LLM |
| HTTP 主链路 | 首页、安全响应头、健康/市场/研究 API、坏 JSON、错误类型、空问题、超长请求、未知路由及不支持的方法 |

## 手工/线上验收步骤

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| M-01 | 打开首页，检查数据模式、Market State、数据时点、置信度和五个核心维度 | 默认真实模式；没有有效数据时显示证据不足，绝不静默展示 demo 数值 |
| M-02 | 查看行情结构、市场宽度、风格轮动和情绪证据详情 | 每项有原始字段/计算口径、来源和时间；来源为扶摇且时点有效 |
| M-03 | 检查流动性卡片 | 本次 MVP 只显示扶摇当日成交额，标记 partial 且 `score=null`；不得引入指数成交额或演示历史基准 |
| M-04 | 检查估值、事件卡片 | 估值和事件均 unavailable、无事实；不得用演示数据或“无事件”补位 |
| M-05 | 输入普通研究问题，如“当前市场整体状态如何？” | 先返回 Research Plan，再读取最近 3 分钟内的校验快照（过期时才取数）；回答区分工具事实与 AI 归纳，事实有 evidence 引用 |
| M-06 | 基于现有会话继续追问风格/流动性 | 继续使用上下文；新问题仍需计划、数据证据和引用 |
| M-07 | 连续刷新首页并从 Research 读取市场证据 | 首页与 Research 共享缓存；资源 TTL 为指数 2 分钟、全市场/涨跌停 4 分钟、日线 45 分钟；同一资源并发调用只触发一次上游请求 |
| E-01 | 缺少扶摇 Key 或模拟 API 失败/429 | 页面明确报告未配置/失败；不回退到演示数据，不假装返回正常结论 |
| E-02 | 全市场快照缺页、分页总数不一致或涨跌字段覆盖不足 | 市场宽度不可用；不从部分页计算全市场宽度/成交额分数 |
| E-03 | 数据过期、未来时间戳、时点缺失或不同指数日线不同步 | 对应维度退出评分；时间状态清晰可见 |
| E-04 | 生产默认关闭 iFinD，或在 opt-in 测试中模拟其失败 | 默认不发 iFinD 请求且不向页面泄露 MCP 技术故障；流动性保留扶摇当日事实并 partial/no score，事件/估值 unavailable；扶摇主链路和 Hard Gate 不变 |
| E-05 | 研究 API 收到坏 JSON、非对象、空问题或超过 12 KB 请求 | 返回恰当的 400/413；正常请求可用 |
| E-06 | 让指数、全市场分页、历史日线、涨跌停接口分别出现超时/中止，再恢复 | 每个接口独立超时且最多重试一次；一个接口的 Abort 不取消其他数据链路；重试恢复后保留完整证据 |
| E-07 | 最近有效快照分别在 freshness 时限内、超过时限后模拟上游失败 | 时限内显示“最近有效快照”和来源实际时点，并降为部分数据；超时限不可用、不标 LIVE，市场宽度无效或核心证据不足时 Hard Gate 生效 |
| I-00 | 不设置 `IFIND_ENABLED`，即使环境中存在 iFinD credentials | 不发 iFinD MCP 请求；事件 unavailable，Research 无事件 citation、不会补写 iFinD 事实；扶摇正常运行 |
| I-01 | 在隔离自动化 fixture 中显式启用 iFinD adapter，返回历史成交额和新闻 | 只验证保留的 optional adapter：历史口径/冲突处理和事件标题 citation；不代表生产依赖或线上启用 |
| I-02 | iFinD MCP timeout 或空结果 | 对应维度清楚显示 unavailable/partial，无演示值；扶摇主链路保持不变 |
| I-03 | iFinD 与扶摇同日成交额差异超过 5% | 双源原始事实及来源/时点保留，流动性标记 conflict 且 score=null |
| H-01 | 模拟少于 3 个有效核心维度（即使残留旧分数） | Hard Gate 显示“证据不足，暂不形成市场状态判断”；不出现方向 Market State、主要矛盾或切换条件 |
| H-02 | 保留至少 3 个其他核心分数，但移除有效市场宽度 | Hard Gate 同样生效；宽度缺失不能由其他维度绕过 |
| C-01 | 输入“现在买哪只股票”“推荐一只股票”“应该几成仓” | 程序在模型规划和数据刷新之前拦截；不返回建议 |
| C-02 | 输入目标价、止损、加减仓、明天确定涨跌或收益保证请求 | 程序级合规拦截；不请求数据工具或模型生成方向性建议 |
| C-03 | 模拟模型返回荐股、买卖或未核验数值 | 二次检查丢弃输出并显示拦截/不可用说明；不以规则模板替代 |
| C-04 | 逐一输入 8 类合法研究问题：市场状态、宽度、风格、行业、流动性、情绪、事件、历史比较 | 不发生合规误杀；有数据时必须走完 Research Plan、读取 evidence、LLM 解释和 citation。无数据主题应如实显示证据不足，不允许伪造答案 |
| C-05 | 用 8 类带具体交易动作、荐股、仓位、目标/止损、方向预测或收益承诺的模型输出尝试绕过前置拦截 | 输出二次检查逐项拦截；不返回违规文本，且该检查不得移除 |
| N-01 | iFinD MCP 对新闻同时返回标题和正文，再查看首页/API/Research | 首页/API/citation 只含标题、日期、来源、链接；LLM 只接收标题；展示受授权许可约束，不暴露新闻正文 |

## API 观察点

- `GET /api/health`：只报告服务存活和运行模式，不回显配置值。
- `GET /api/market`：检查 `demo=false`、数据源状态、时间、warnings、assessment、维度 facts/source/asOf 和评分是否为空。
- `POST /api/research`，请求体 `{"question":"当前市场整体状态如何？"}`：检查 Research Plan、工具状态、AI 归纳、evidence 引用、模型模式和免责声明。
- 合规检查可用买卖/荐股/仓位测试问句验证；需确认违规请求没有工具调用。
